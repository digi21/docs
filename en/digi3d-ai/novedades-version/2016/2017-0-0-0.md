# Digi3D.AI 2017.0.0.0

Released on 8/29/2016.

## New features

* Simultaneously 32- and 64-bit program installation. Not it's posible to simultaneously install the 32- and 64-bit program on the same machine.
* New command to create centroid for polygons that have no centroid. The Topology menú was also restructured and this new option was added.
* Added options when exporting topology. We added options when exporting topologies that can indicate whether the Z coordinate of the polygon drawn from the centroid is 2.5D or 3D.
* Added native support Pix4D's projects. Now the program loads natively Pix4D projects.
* [Added native support PhotoScan's projects](http://blog.digi21.net/2015/12/29/carga-nativa-de-archivos-de-calibracion-de-camaras-de-pix4d/). Now the program loads natively PhotoScan projects.
* [Changes in camera files](http://blog.digi21.net/2016/01/04/cambios-en-el-sistema-de-camaras/). We've make changes in the camera files to be able to emulate any camera with our propietary format.
* [Added option to select the order of the axes in the projected CRS](http://blog.digi21.net/2016/01/17/mejoras-en-el-cuadro-de-dialogo-de-seleccion-de-sistema-de-referencia-de-coordenadas-en-digi3d-net/). Is has added an option for allow to select the order of the axes in projected coordinate reference systems
* [Native load of Inpho's satellital projects](http://blog.digi21.net/2016/01/17/carga-nativa-de-orientaciones-satelitales-de-archivos-de-proyecto-de-inpho/). Added the possibility to load Inpho's satelligal projects: with geographical and projected coordinate reference systems.
* [Native load o JPEG format image files in the photogrammetric window](http://blog.digi21.net/2016/01/19/carga-nativa-de-archivos-jpeg-en-la-ventana-fotogrametrica/). Now you can load JPEG images in the photogrammetric window.
* [Added the ability to disable cameras extensions when loading the program](http://blog.digi21.net/2016/01/24/truco-haz-que-digi3d-net-consuma-menos-memoria-y-arranque-mas-deprisa/). With this option you can load more quickly and consume less resources if you disable camera files you don't use.
* [Added flag to insert automatically vertices in the intersections of the line that is just drew](http://blog.digi21.net/2016/03/13/insertando-automaticamente-puntos-en-las-intersecciones-al-finalizar-una-linea/). With this new flag, the program will generate the vertices automatically.
* Now the TENTATIVE\_INSERT adds vertex to entities of type polygon
* [Added intelligence to verify geometric relationships between entities](http://blog.digi21.net/2016/02/23/relaciones-geometricas-entre-entidades/). Now the program is capable of analyzing crowd of geometric relations between point-point, point-line, point-area, etc.
* Added checks for compatibility between the scheme between a .DBF file the active codes table. Now the program detects more rigorously problems of compatibility when loading shapefiles.
* [Added analysis of semantic model in real time](https://blog.digi21.net/2014/12/16/control-de-calidad-en-tiempo-real-con-la-nueva-funcionalidad-desencadenadores-de-digi3d-net/). The program is now able to analyze geometric relationships between entities in real time, displaying error messages to the user in the same instant that is digitized an entity.
* [Added a command to rotate the images in the photogrammetric window in real time](http://blog.digi21.net/2016/03/18/rotaciones-de-las-imagenes-en-la-ventana-fotogrametrica/). It was added an option in the photogrammetric window menú to the menu to execute this command.
* [Visual Themes](https://blog.digi21.net/2016/04/14/temas-visuales-en-digi3d-net/). Now you can select the theme that the application displays for menus, toolbars, panels and dialog boxes.
* [Code alias](https://blog.digi21.net/2016/04/14/alias-de-codigos/). Now you can add alias to the codes, to select a code using an alias.
* Improvements in the communication of errors when loading Geomedia's drawing files when detecting the code of the entity for tables with condition attributes.
* [Added comparison operators in field conditions](https://blog.digi21.net/2016/09/30/seleccion-automatica-de-codigo-en-funcion-de-atributos-de-base-de-datos-al-cargar-shapefiles-o-geomedia/). Now you can indicate that Digi3D.NET should select a particular code if an attribute has a value greater than, greater than or equal, or less than or equal to a specified value.
* Added possibility to select the field name to be displayed on the database attributes panel. Now you can indicate whether you want the field name, the title of the display field, or both.
* Added support to load NTF's RPC files.
* Now the satellital sensor shows the parameters of the RPCs when selecting the Photogrammetric Window/Information menu option
* New properties of the selected entity panel. This new panel allows you to display database attributes of the entity that is just selected.
* Now the XYZLINE command allows you to select entities reference files.
* Added the ability to group database fields. https://blog.digi21.net/2016/05/20/agrupando-grupos-de-atributos-de-bbdd-en-digi3d-net/
* Added support for EXIF rotation rotation parameters interpretation in JPG files
* [Added support for commands to be execute when selecting a a code](https://blog.digi21.net/2016/06/30/acciones-a-ejecutar-al-seleccionar-cualquier-codigo-de-una-tabla-de-codigos/). Now you can indicate the series of commands to be executed when a code is selected.
* [Addes a quick-change photos when loading photogrammetric projects](https://blog.digi21.net/2016/07/04/cambio-rapido-de-imagenes/). Now you can load into the photogrammetric projects panel a project created with programs that have no concept of stereoscopic pair.
* [Added scripts in the code table](Ahora se puede ejecutar un guion en cualquier lenguaje de programación .NET asociado a un código, de manera que cuando se almacena una entidad se puede añadir lógica de negocio.). Now you can run a script in any .NET programming language associated with a code, so that when an entity is stored can add business logic.
* Added methods of calculating perimeters to the managed calculator. We added the methods CalculatePerimeter2D and CalculatePerimeter3D to Digi21.DigiNG.GeographicCalculator type.
* Now the importer Geomedia extension provides database attributes of a particular entity. With this .NET programming scripts can access databases attributes of a given entity.
* Added types administrator to analyze geometric relationships between entities. Added the site administrator to compare relationships between entities: Point Point, PointLine, PointArea, LineLine, LineArea, AreaArea
* Improvied communication errors for A3 sensor (Quasi Panoramic). Now if you can't load the .dat file, the software shows a dialog box to the user indicating possible cause could be that that the path of the file has special characters such as accented letters, etc. The libraries provided by VisionMap doesn't allow routes upload files with special characters.
* [Added calculation of epipolar rectification parameters to A3 sensor (VM-QuasiPanoramic)](https://blog.digi21.net/2016/07/15/mejoras-en-el-sensor-de-la-camara-a3-vm-quasipanoramic/)
* [Macros in the code table file](https://blog.digi21.net/2016/07/18/macroinstrucciones-en-el-archivo-de-tabla-de-codigos/). Now you can store macros in the code tables Digi.tab.xml
* [Speech recognition](http://blog.digi21.net/2016/07/19/comandos-de-voz). Now the program can recognize voice commands previously assigned in the code table.
* [Now when changing the current model using the panel photogrammetric project, the images can be automatically rotated and swapped if necessary](https://blog.digi21.net/2016/08/11/no-pierdas-el-norte/). We have added two options to dialog settings that allow you to configure whether to exchange the images (and rotate) to change the model using the panel photogrammetric project to ensure that the orientation of the model being loaded matches the loaded model.
* Eliminated from the Settings dialog box the Transformation of images on the fly settings. Configurations appearing in this section were not necessary because now Digi3D.NET transformates the images by hardware.
* Added a dialog to add references to assemblies in the code table
* Improved performance when loading code tables. Now the code tables are loaded much faster than in previous versions.
* Added exceptions to communicate database attributes errors in scripts triggers. The next exceptions have been added: Digi21.DiggiNG.DigiTab.Excluded EntityException, Digi21.DigiNG.DigiTab.DatabaseAttributeException the Digi21.DigiNG assembly.
* Now the 32- and 64-bit versions of Digi3D.NET shares OpenGis settings. You do not need to manually copy the geoid model EGM2008 in the specific folder for 64-bit version.

## Fixes

* Fixed a problem when adding tags per table in the code tables editor. It was adding the label to the next code, not the code that was intended to add the label.
* The program crashed when compressing with newly installed program. This problem has been fixed.
* The MOD and MOD\_Z commands unexpectedly terminated the program when modifying a polygon with holes.
* The Z commandr was not modifying the Z coordinate in the photogrammetric window if it was blocked
* Fixed an issue in listed entities Digi21.DigiNG.DrawingFile. These entities did not have assigned the Owner property, so that they could not access the database properties associated with the entity as the owner file drawing was unknown.
* Fixed an issue with pyramidal levels generator. The program may terminate unexpectedly while processing a character string sent by the LibTIFF library.
* SPEED order does not show the dialog if there open a window drawing. It was solved this problem as well as a related issue in the OPEN\_BING\_MAPS, CHANGE\_BRITHNESS\_CURSOR, NIVELATION\_MATRIX, SHOW\_CORRELATION\_FACTOR, and ZOOM\_SPEED commands.
* Fixed an issue when calculating orthophotos if the SRC of the drawing window does not match the sensor SRC. This problem has been fixed. Now the CAL\_ORTO command performs the coordinate transformation between the coordinate reference system of the drawing window (the SRC in which the orthophoto is calculated) and the coordinate reference system of the photogrammetric window.
* Fixed an problem with the EGM2008 engine. It has located a problem related to the EGM2008 engine that could cause the program to finalize unexpectedly if multiple threads running simultaneously EGM2008 requested data to the grid.
* Photogrammetric window does not display the midpoints. We disabled this option time ago when we added hardware image rotation. Now we returned this functionality to the system.
* The program ends unexpectedly when creating pyramid levels with JPEG compressed TIFF files
* The program ends unexpectedly if the load of a drawing file is canceled because it is not located the code table specified in the Drawing File tab
* Fixed an issue in the File Projects Configuration dialog box. The program did not show the coordinate reference system for the drawing window in the settings correctly. This was a minor problem as the view of drawing itself correctly loaded the corresponding reference system coordinates.
* The LIST command doesn't shows 3D perimeters correctly. It has solved this problem affecting commands requiring 3D modules in projected coordinate reference systems, calculating the perimeter was 2D and not 3D.
