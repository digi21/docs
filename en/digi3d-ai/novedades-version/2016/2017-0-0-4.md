# Digi3D.AI 2017.0.0.4

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Released on 11/4/2016.

## New features

* [Now the dynamic menus that display labels can display only labels loaded geometries codes](https://blog.digi21.net/2016/10/28/menus-dinamicos-mas-dinamicos-que-nunca/)
* [Improvements when communicating errors about topology analysis](http://blog.digi21.net/2016/10/31/mejoras-en-la-comunicacion-de-errores-en-los-analisis-topologicos-de-digi3d-net)
* [New command SELECT\_FLOODING](http://blog.digi21.net/2016/11/02/nueva-orden-selecciona_inundacion). This new command allows you to send the lines forming the outer contour of the polygon or polygons selected by flooding to the commend is running at this time.
* [New command REN\_COD\_SEL](http://blog.digi21.net/2016/11/03/nueva-orden-renomcod_sel). With this command you can rename a code of all selected entities.
* [Now if an error is found in the semantic model when storing a geometry the program asks to the user if store it or not](http://blog.digi21.net/2016/11/04/mejora-al-detectar-un-error-de-modelo-semantico-al-almacenar-una-geometria)
* Added possibility to indicate in the DB scheme that a field is of type DATE
* Now is not mandatory to link a code table in the code table so that it can be exported to Shapefile

## Fixes

* The "Help" menu option is displazed in the spanish version of the application
* The topological analysis from the dinamic menus sometimes doesn't analize polygons without centroid
* Solved a problem with the name of the composite CRS for some cases with the conic sensor.
* Fixed a problem detecting if two areas are overlapping
* Extensions compiled for a version of the 2017 branch not work if the upgrade to a newer version. We solved this problem by publishing .NET assemblies with version number 2017.0.0.0
* Tentative panel does not display a history of the tentative
* If when loading a conical model with CRS without vertical component the user indicates that it is unknown, the title of the SRC formed is incorrect
* The polygon's area is not stored in the .DBF associated with a shapefile in fields using the macro ENTITY\_AREA
