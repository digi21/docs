# Digi3D.AI 2018.0.10.0

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Released on 3/16/2018.

## New features

* [Loading of. PYR files is now supported. In addition, the pyramid level generator program can create. PYR files.](http://blog.digi21.net/2018/03/18/anadido-soporte-para-archivos-pyr)
* Modified the calculation of the leveling matrix for satellite images. Now supports both geographic and UTM RPC parameters
* Added support for loading Inpho's PRJ satellite-type files with corrected coefficients. If corrected coefficients are found, these are loaded if not, the originals are loaded.
* Now when loading Inpho project files for satellite sensor, the program does not assume that the coordinate reference system is geographic WGS84, but it gets the system from the .PRJ file.
* Summit Evolution's project file loader for satellite sensors now supports loading projects that are not epipolarized
* [You can now configure whether you want the program to request the vertical coordinate reference system in case the loaded photogrammetric model provides one in 2D.](http://blog.digi21.net/2018/03/18/evitando-que-digi3d-net-solicite-el-sistema-de-referencia-de-coordenadas-vertical-si-la-orientacion-del-sensor-no-lo-proporciona) We can configure this behavior in Tools/Configuration/Coordinate Reference Systems/Request Vertical System for Sensors
* [Now the Pix4D importer also loads the files \_calibrated\_external\_parameters.txt](http://blog.digi21.net/2018/03/18/mejorado-el-soporte-de-pix4d). In this way you can now load these files unmodified (until now you had to rename them to .EO in addition to deleting the image extensions for each of the orientations it contains)
* [Added support for approximating epipolars in satellite images](http://blog.digi21.net/2018/03/18/anadido-soporte-para-aproximar-epipolares-en-las-imagenes-satelitales)
* Added in the photogrammetric window menu an option to calculate the epipolar rectification of satellite models
* [Simplified the Photogrammetric Window/Image Transformation menu when loading a conical sensor model](http://blog.digi21.net/2018/03/18/mejoras-de-interfaz-de-usuario-para-epipolares-para-el-sensor-conico). A single option for epipolar calculation is now displayed. Also, if the current rotation matches the epipolar orientation, a mark is displayed in the menu. The type of epipolar to be calculated can be indicated in the configuration when selecting the option.
* [Improved error communication when loading satellite and conic sensor models](http://blog.digi21.net/2018/03/19/mejoras-en-la-comunicacion-de-errores-al-cargar-modelos-satelitales-y-de-camara-conica). Now the RPC extensions only try to load the file if it is compatible and launch exceptions with errors in case of locating any errors in the file. Now the loader does not capture the exceptions but passes them on to Digi3D.NET for display to the user.
* The .EO file loader now allows the image extension to appear in the.EO file. Until now, the program only located the orientations of the images if the image extension did not appear in the.EO file. As more and more programs generate.EO files in which the photo extension is added to the first column of the orientation, we have modified the program to be able to locate the orientation whether the extension appears or not.

## Fixes

* If a.TIF file is loaded and warnings are generated, the program generates memory leaks.
* When loading satellite models the program can leave memory leaks
* Fixed problem when projecting\_dem, it could be the case that the number of calculated rows and/or columns does not match the expected number of rows and/or columns.
* Fixed a problem with IR\_PRINCIPLE when Z of the photogrammetric window was blocked
* Fixed a problem where when changing the display parameters of a classification in an LAS file, the changes were not seen in the photogrammetric window until it was closed and reopened.
* Fixed a problem when a cartography quality test returned more than one incident for the same entity, when double clicking on the task, an incorrect geometry was shown.
* Fixed that if an exception of the DatabaseAttributeException type was released, no tasks were generated in the task pane.
* If an unknown error is found when loading a photogrammetric project using the Photogrammetric Projects panel, the program ends unexpectedly.
* If multiple calibrations for one camera appear in a PhotoScan project file, the first one is always loaded regardless of whether it is the set one or not.
