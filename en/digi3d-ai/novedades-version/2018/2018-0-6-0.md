# Digi3D.AI 2018.0.6.0

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Released on 2/14/2018.

## New features

* [New command SHAPE\_POLYGON](https://blog.digi21.net/2018/02/19/nueva-orden-formar_poligonos/)
* Added support for storing virtual geometries in database based drawing files such as Shapefiles
* You can now configure whether the tentative is accepted with the Data button/pedal if the order being executed is the LINE command. This new configuration option appears under Tools/Configuration/Snaps
* Added a configuration option to indicate whether at the end of the INSERT\_HOLE command it removes the line you selected as a hole.
* The MOD\_MULTIPLE command does not remove the line that defines the new geometry when it is finished.
* Now the commands do not perform unnecessary screen regenerations when the user moves over a polygon that has already been filled with color
* Now when executing the commands TASK+ and TASK- for the tasks that move the drawing window to certain coordinates, if we have a photogrammetric window open, it also moves.
* Added support to duplicate polygons with the command DUP

## Fixes

* Solved a problem in the calculation of centroids in polygons. The centroid in polygons with holes was not being calculated correctly.
* When going to the point of origin in PhotoScan models with camera/reference nodes the program leads to incorrect coordinates. Now if the program locates the zMedia attribute it ignores the camera/reference node, because the Z coordinate that appears in the camera/reference is not in the field. Now the program also assumes that the coordinates displayed in camera/reference are always geographical coordinates.
* Tiled TIFF files with rectangular rather than square tiles are displayed with artifacts
* The ORIGIN\_SHIFT command duplicates the polygon if what shifts is the origin of a hole in the polygon.
* Some commands duplicate geometries when running with the flag AUTO\_INSERT\_VERTEX\_INTERSECTION\_WHEN\_FINISH\_LINE. The behavior of the program has been modified when storing geometries with the AUTO\_INSERT\_VERTEX\_INTERSECTION\_WHEN\_FINISH\_LINE flag activated. Geometry modifications that intersect with the geometries that have just been stored are now made after finishing each order rather than every time an order adds a geometry to the drawing file.
* Sometimes the program displays certain geometries that have a code whose display is disabled. It has been detected that if a eliminated geometry was recovered, it was never stopped displaying even though some command ordered that it not be displayed.
* Sometimes when forming flood topologies, the program consumes more and more memory.
* Since the functionality of displaying multiple semantic errors in a single geometry was added, when performing the on-demand analysis the program does not display errors in the task list.
