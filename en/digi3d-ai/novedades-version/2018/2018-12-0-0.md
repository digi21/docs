# Digi3D.AI 2018.12.0.0

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Released on 10/21/2018.

## New features

* Added support for Boolean values to the PostGIS extension
* Boolean type values in the database properties window can now display NULL type values
* Improved error capture module to generate error reports if the program ends unexpectedly
* Now a project file can reference .D3D files in different directories
* Shapefile files can now be loaded without an associated database (.DBF)
* Added the property "Copiable" to the database fields.
* Modified PostGIS importer/exporter to not copy non-copyable fields when copying database attributes from one geometry to another.
* Now it can be indicated in the configuration parameters of the classic binary file importer that the table number 1 is interpreted as a table and not as the internal Digi table. Historically table 1 meant "no database link" in the classic BIN files, so the first database table had to be necessarily table 2. With this modification we can avoid this restriction.
* Recompiled all the program with Visual Studio 2017 and thanks to it you can start programming in C++ 17
* DWG and DGN libraries updated to Teigha 2019
* Added support for displaying labels of all types of geometries in the BBDD attribute viewer
* Updated XTreme ToolkitPro user interface library to version 18.4.0
* Updated Erdas ECW library to version 5.4.0
* Updated Glew library to version 2.1.0
* Updated LibJPEG library to version 9.3.0
* Updated LibPNG library to version 1.6.36
* Updated LibTIFF library to version 4.0.6.2
* Updated MrSid library to version 9.5.4.4709
* Updated ZLib library to version 1.2.11
* Added support for INTER\_EJE command to work with polygons or closed lines
* Added support for INSERT\_HUECO command to insert polygons as holes
* Added in the configuration dialog box parameters to indicate what to do with the geometry used in INSERT\_HUECO: nothing, delete it or ask.
* DotNET programs within code tables can now be referenced assembled by their safe name rather than by the path in which they are located.
* New command POL to draw a polygons
* The LINE command can now be terminated by pressing the ESC key if no vertex has yet been digitized.
* Improved the algorithm of UNIR\_POLIGONS that now keeps the outer contour of the geometry and does not require the original polygons to have common faces.
* Added support to load shapefiles with Z coordinates of type not-a-number
* Added programming type Digi21.DigiNG.Topology.DuplicityDetector to detect duplicate geometries.
* Improved performance by storing geometries in Shapefiles using Digi21.DigiNG.IO.Shp
* Fixed a problem where when storing geometries using Digi21.DigiNG.Io.Shp.Add in overload with dictionary database geometry was stored twice.
* Fixed a memory build-up problem when working with Shapefiles when accessing a database record
* Fixed a memory leak in the Digi21::DigiNG::IO::Shp::Add method related to the database attributes to be stored along with the geometry.
* When mining complexes in Shapefile files, geometries that were part of the complex lose their database attributes.
* Added builders to Digi21.DigiNG.IO.Shp.Shp that allow to specify the CODEPAGE to assign to the database to create.

## Fixes

* The PostGIS extension does not respect the window sizes of the region of interest assigned in the drawing files panel
* If the program detects an error it does not send the error report to the Digi21 servers.
* If the layer selection dialog box is cancelled when a PostGIS file is loaded, the program ends unexpectedly.
* The dynamic help panel does not display the help file specified in the configuration
* If you try to generate a geometry on a PostGis connection on an unloaded layer the program ends unexpectedly.
* If the RECHARGE\_ARCHIVES\_REFERENCE\_VISTA command is executed in the middle of the execution of another order, geometries may be duplicated or the program may unexpectedly end. Now the order RECARGAR\_ARCHIVOS\_REFERENCE\_VISTA does not allow to be executed if an order is being executed, to avoid releasing the geometries used by that order.
* Cannot run semantic model programs on Windows 8
* Intersection detection calculations in BINTRAM do not work correctly with sigmas greater than or equal to 1.
* The PARALLEL command from the command line locks the program if the drawing file has deleted geometries.
* The database panel the program displays fields from another table when loading a Shapefile
* Real numbers stored in an XBASE database (.dbf associated to shapefiles) in NUMERIC type fields are not correctly interpreted.
* The photogrammetric window does not show dots from certain LAS files
* The Digi3D.NET online installer does not install Acces Database Engine on 64-bit computers.
* Table Editor program loads import/export extensions twice
* The program does not allow you to attempt complex entities
* When instantiating an object of type Digi21.DigiNG.IO.Shp with any of the constructors that do not have a code table, the program ends unexpectedly.
* The program attempts file geometries whose display has been disabled in the drawing file panel
* When working with SHP files and compressing, the database attributes of the geometries do not correspond to what they should. Solved a problem when compressing SHP files, the indexes in memory to the database records moved a unit, so that if we had two entities one with attribute "a" and another with "b", after compressing, the first was with null attribute and the second with "b". When the file was opened again, it was solved.
* The program does not allow to load shapefiles with databases with information between the header and the database data.
* Fixed a problem in Digi21.DigiNG by which to instantiate from a console program an object of type Digi21.DigiNG.DigiTab.DigiTab it did not load the importers / exporters installed in Digi3D.NET.
* Solved problem where it is possible that some codes are not displayed in the drawing window
* Fixed a problem by which importers managed as Digi21.DigiNG.IO.\* did not calculate the maximums and minimums of geometries loaded so that spatial operations gave error.
* Fixed a problem of representation in the rotation of texts in the photogrammetric window. The kappa rotation of the image was not being respected.
* Fixed a problem where changing the code while digitizing a line could unexpectedly end the program.
* Fixed problem where the dynamic parallel order was not finished when the Cancel button was pressed.
* Solved problem by which if it was acting the COD\_CURVAS and snapping in a geometry the program cut the geometry that was being digitized.
* Fixed problem where if no layer was selected to load in Geomedia the program ended unexpectedly.
