# Digi3D.AI 2027.0.0.431

## New features

* [With software licenses, the «Activate with a code...» button activates the computer with a license activation code, for the current Windows user or for all Windows users of the computer](https://www.digi21.net/Ayuda/p/licencias-de-software)
* [New command-line command /activar-equipo \<code\>: activates the computer for all Windows users without showing any window; it requires running Digi3D.exe with administrator permissions](https://www.digi21.net/Ayuda/p/activar-equipo)
* [With software licenses, a license can have a maximum number of simultaneous sessions, which are distributed through digi21.net or through a local license server](https://www.digi21.net/Ayuda/p/sesiones-simultaneas)
* [Local license server: a Windows service with its own installer (default port 21021) and a web administration panel, to distribute simultaneous sessions inside the customer network](https://www.digi21.net/Ayuda/p/servidor-de-licencias)
* [The Digi3D.AI installer accepts the SERVIDOR\_LICENCIAS=\<url\> property, which writes the local license server address on the computer; it allows configuring it when deploying with group policies](https://www.digi21.net/Ayuda/p/servidor-de-licencias)
* [New CLOUD\_ORI command (orientations menu of the PointCloud sensor): it computes the similarity transformation from the cloud to the control points measured with the 3D cursor and saves it in the cloud's .transform.json file](https://www.digi21.net/Ayuda/p/ori-nube)
* The PointCloud sensor and the PointCloud importer apply to each cloud the transformation of its .transform.json file, which Lot Of Points and CLOUD\_ORI write, and use the reference system of the crs\_wkt key if the file has it
* [The photogrammetric window animates pans to given coordinates, such as those of GO\_TO\_CONTROL\_POINT, GO\_TO\_ORIGIN\_POINT or go\_to with goto\_snap; moving the handwheels or the mouse, pressing a pedal or running a command stops it](https://www.digi21.net/Ayuda/p/duracion-minima-del-desplazamiento-animado)
* [Configuration, Photogrammetric window: options for the minimum duration (0.3 s; 0 disables the animation), maximum duration (1.0 s) and maximum distance (5 drawing area widths) of the animated pan](https://www.digi21.net/Ayuda/p/duracion-minima-del-desplazamiento-animado)
* [The AI chat panel can attach images (PNG, JPEG, GIF and WebP), PDF documents and UTF-8 text files of up to 100,000 bytes with the «Attach files» paperclip button](https://www.digi21.net/Ayuda/p/asistente-ia)
* [Internet communication: «Connection type» only offers «Direct» and «Windows proxy settings»; a configuration saved with «Proxy server» becomes «Windows proxy settings»](https://www.digi21.net/Ayuda/p/tipo-de-conexion)
* [Digi3D.AI opens GeoPackage versions 1.2.1, 1.3 and 1.4, in addition to 1.2.0](https://www.digi21.net/Ayuda/p/geopackage)
* [In the code table editor, when a centroid is added, «Z coordinates of the polygon» starts as «The one specified in the topology» instead of «From the centroid»](https://www.digi21.net/Ayuda/p/anadir-centroide)
* When a version adds a new panel, such as the CLOUD\_ORI panel, Digi3D.AI creates it and keeps the panel layout saved by the user
* New 3D models sensor: displays OBJ meshes and 3D Tiles tilesets in stereo from local files or from http and https URLs, including Azure Blob Storage with a shared access signature (SAS), with mouse and SpaceMouse navigation
* The 3D models sensor suggests and validates the coordinate reference system (CRS) of the models when the project is created, and saves in the .d3d file the file paths, the CRS and the on-screen error threshold
* When a project with OBJ meshes is opened, the 3D models sensor reads them in a worker thread and shows a progress dialog that can cancel the loading, instead of leaving Digi3D.AI unresponsive
* The 3D models sensor applies the WebP textures of .glb models (EXT\_texture\_webp extension) and discards the fragments of materials with alphaMode MASK whose alpha is below the cutoff threshold
* The 3D models sensor panel has the Camera category (stereo base and vertical field of view) and the SpaceMouse category (speeds and checkboxes that cancel pitch, yaw and translation)
* The toolbar of the 3D models sensor has the automatic Z button and the buttons of the six standard camera views: Top, Bottom, Left, Right, Front and Back
* [CLOUD\_ORI: each control point is used in XYZ, in XY only or in Z only, and the panel computes the orientation in real time while it waits for the pedal](https://www.digi21.net/Ayuda/p/ori-nube)
* [CLOUD\_ORI: two panel checkboxes show or hide in the photogrammetric window the marks of the measured points and those of the computed points](https://www.digi21.net/Ayuda/p/ori-nube)
* [CLOUD\_ORI: when a computed transformation is accepted, the command writes the adjustment report to \<original\>.transform.txt, with a table of the coordinates measured in the original cloud file](https://www.digi21.net/Ayuda/p/ori-nube)
* PointCloud: «Export transformed cloud...» (orientations menu) writes each local cloud to a LAS or E57 file with the transformation of its .transform.json file, without overwriting the originals; from an E57 it keeps scans and images
* The affine, exterior and absolute orientations of the image sensors and the RPC block adjustment show in the images the measured points and the computed position of the chosen point, with checkboxes to hide them
* [Stereoscopic orthophoto: at most about 32 MiB of tiles are uploaded to the GPU per frame, and the automatic Z and tile loading visit fewer tiles, so panning over a large orthophoto is smoother](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* [The Photogrammetric project panel loads a project published at a URL (Azure Blob Storage or another HTTP or HTTPS server), saves its authorization (SAS) encrypted and can renew it, open the local folder and discard the local copy](https://www.digi21.net/Ayuda/p/cargar-proyecto-remoto)
* [The frame camera sensor opens the TIFF images of a remote project over HTTP, downloads the tiles and the associated model files in parallel and limits the remote image cache on disk (20 GiB by default)](https://www.digi21.net/Ayuda/p/publicar-proyecto-fotogrametrico-remoto)
* [In a remote project in Azure Blob Storage, the Inpho, Summit and PhotoScan loaders skip the models whose photos are not published; the SAS needs list permission (sp=rl) or the container needs anonymous listing](https://www.digi21.net/Ayuda/p/publicar-proyecto-fotogrametrico-remoto)
* [Raster2Digi creates Cloud Optimized GeoTIFF (COG) files, with the pyramid levels inside the file, also from TIFF files that are already tiled, with the self-contained pyramid levels option (enabled by default)](https://www.digi21.net/Ayuda/p/generador-de-niveles-piramidales)
* [When converting a local TIFF that Digi3D.AI cannot read, or that has no pyramid levels, Digi3D.AI writes a COG with the original name and keeps the original file as \<name\>\_\_N](https://www.digi21.net/Ayuda/p/localizada-una-imagen-no-preparada-para-digi3d-ai)
* Tiled images, local or remote, load first the tile closest to the last drawn point, which before was the first in the queue, and a pending tile is no longer queued twice
* [.NET programming: the Digi21.DigiNG.Topology 26.1.0 NuGet package builds the topologies defined in the feature table and creates their polygons, like BINTOP and TOPOLOGIA\_A\_POLIGONO, from an external program](https://www.digi21.net/Ayuda/p/digi21.diging.topology.topologyanalyzer)
* [.NET programming: the new Digi21.DigiNG.Dtm NuGet package opens a .mdt digital terrain model and gets the terrain Z at a point from an external program](https://www.digi21.net/Ayuda/p/digi21.diging.dtm)
* [The residual lists of the interior, relative, absolute and affine orientations, of the point cloud orientation with control points and of the RPC block adjustment show in red the cell with the largest absolute value in each residual column](https://www.digi21.net/Ayuda/p/ajuste-en-bloque-de-rpcs)
* [The Create model and New project dialog boxes let you choose the .d3d file name, and a model opened from a renamed .d3d file is saved to that same file and keeps its orientation files](https://www.digi21.net/Ayuda/p/crear-modelo)
* Digi3D.AI has a single installation for the dongle and for software licenses: on startup it uses the software license activated on the computer and, if there is none, the dongle
* If the computer has no activated software license and no dongle with a Digi3D.AI license, Digi3D.AI shows the Digi3D.AI protection dialog box, which lets you activate a software license or select the dongle
* With software licenses, the Help \> Software licenses... command shows the license status of the computer and the licensed modules, and lets you activate this computer, cancel the registration and renew the usage authorization
* With software licenses, the DTM commands and the DTM importer use MDTopX if the software license includes MDTopX
* The Digi3D.AI installer no longer installs the SafeNet license applications suite by default; in an installation without interface it is installed with INSTALAR\_SUITE\_LICENCIAS=1
* [With the dongle (HASP key), Help \> Software licenses... lets you activate software licenses, which Digi3D.AI uses the next time it starts; the «Use the HASP key» button removes the activation of the computer and closes Digi3D.AI](https://www.digi21.net/Ayuda/p/licencias-de-software)
* With a HASP key that does not have this computer activated, the warning dialog adds the «Use a software license» link, which opens the Software licenses dialog; before, it only allowed activating the computer or selecting another key
* The Software licenses dialog shows the reason why digi21.net rejects the registration of the computer, for example that the computer data for its fingerprint cannot be obtained or that the limit of requests per IP address was exceeded
* If the license has no free seats after activating the computer with a code, the Software licenses dialog says so and asks you to request Digi21 to revoke the activation of another computer
* DigiTab, Raster2Digi and CreaArchivoHmp show the protection and Software licenses dialogs with the theme configured in Digi3D.AI; before, they used the system colors

## Fixes

* [Command line: the dgn subcommand accepts the drawing file path; before, «Digi3D.exe dibujo ... dgn» did not open any window](https://www.digi21.net/Ayuda/p/dgn-2)
* [When exporting to Shapefile entities from a drawing file with no associated database, fields with a default value, such as those using %CODE\_VALUE=...%, were left blank and only the Id field was filled](https://www.digi21.net/Ayuda/p/shp)
* [In Shapefile, fields with names longer than 10 characters were left blank when editing an entity read from a .shp, when adding a new entity to an open .shp, or when exporting to a new .shp](https://www.digi21.net/Ayuda/p/shp)
* [When importing a Shapefile into a GeoPackage or FileGDB table, columns whose name differs from the attribute in letter case or in the 10-character truncation of the .dbf were left NULL](https://www.digi21.net/Ayuda/p/geopackage)
* [In GeoPackage, deleting several entities of a table (for example with delete\_cod) and compressing in the same session did not remove them from the file: they were still there when it was reopened](https://www.digi21.net/Ayuda/p/geopackage)
* [When adding a reference system to a GeoPackage with the gpkg\_crs\_wkt extension, Digi3D.AI wrote an empty string in definition\_12\_063; it now writes «undefined»](https://www.digi21.net/Ayuda/p/geopackage)
* [LEAVE did not remove the reference file from .reference\_files.json if it was a Shapefile or a FileGDB or if the active drawing file had changed, and the file was loaded again when the drawing file was opened](https://www.digi21.net/Ayuda/p/dejar)
* The conic sensor showed «Unable to open the file» when opening a model whose aerial triangulation file was in a folder with non-ASCII characters, such as «ñ» in D:\\Adif\_Logroño
* [Control point files: the header of a CSV was loaded as a point at (0, 0, 0) and lines with invalid coordinates were read without a warning; the header is now ignored and invalid lines are reported](https://www.digi21.net/Ayuda/p/archivo-de-puntos-de-apoyo)
* [ABSOLUTE\_ORI and aerotri closed the program with a sensor that is not conic, such as PointCloud; they now show the balloon «This command is incompatible with the active sensor»](https://www.digi21.net/Ayuda/p/ori-absoluta)
* [Starting an orientation command while another one was active cleared the marks, unlocked the cameras and moved the view of the active orientation](https://www.digi21.net/Ayuda/p/ori-absoluta)
* [With another command on top of an orientation command, OK and Cancel removed that command; the buttons are now disabled and a balloon says «Finish the active command before accepting or canceling the orientation.»](https://www.digi21.net/Ayuda/p/ori-absoluta)
* [Closing Digi3D.AI with an absolute orientation that had not been accepted could close the program unexpectedly](https://www.digi21.net/Ayuda/p/ori-absoluta)
* [If saving the .abs.xml file or opening the .mod file failed when accepting an absolute orientation or an aerial triangulation measurement, the sensor kept the new orientation; it now keeps the previous one](https://www.digi21.net/Ayuda/p/ori-absoluta)
* [In the RPC block adjustment, if an adjustment file could not be written when OK was clicked, the command failed without a warning; it now shows «Error opening file: ...» and the command stays open, and it warns if the report cannot be saved](https://www.digi21.net/Ayuda/p/ajuste-en-bloque-de-rpcs)
* [round\_coordinate with fewer than two parameters and tag\_contours when the code selection dialog was cancelled repeated endlessly with REPEAT enabled; round\_coordinate closed the program with a stack overflow](https://www.digi21.net/Ayuda/p/redondea-coordenada)
* With two editors in the status bar, the buttons of the first no longer stay in the bar with no active command and the second is not placed below; opening the second cancels the command name capture of the first, which went to the second
* DigiTab showed swapped messages for an encrypted code table package and for a package without a table file
* [In the PointCloud sensor, the standard view buttons rotate the camera around the cursor and leave it behind it; before, the cursor could end up in the camera plane and its coordinates were shown as -nan(ind)](https://www.digi21.net/Ayuda/p/point-cloud)
* [In the PointCloud sensor, the tooltip and the description of the Bottom button showed "Enabled" / "Activada"; now they show "View from the bottom" / "Vista desde abajo"](https://www.digi21.net/Ayuda/p/point-cloud)
* [GO\_TO\_ORIGIN\_POINT of the PointCloud sensor uses 10 units as the distance if DistanciaCamaraIrPuntoOrigen is not finite or is smaller than the near plane; with 0 the camera stayed at the cursor](https://www.digi21.net/Ayuda/p/point-cloud)
* Closing or removing a reference file, or compressing the drawing file, with a point cloud or stereoscopic orthophoto sensor did not free its OpenGL objects and could delete OpenGL objects of another window
* [When a point cloud was imported, an exception other than std::exception closed Digi3D.AI; now the error is shown, and if reading fails the temporary file of the level of detail cache is deleted if possible](https://www.digi21.net/Ayuda/p/pointcloud)
* [Stereoscopic orthophoto: an ancestor tile is drawn only in the areas of the tiles not yet loaded; before, it hid the sibling tiles already loaded and a mix of two resolutions was visible on terrain with relief](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* [Stereoscopic orthophoto: with non-square pixels, tiles are drawn with their size in Y; before, there were undrawn or overlapping strips between rows of tiles](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* [Stereoscopic orthophoto: the automatic Z reads the height of the point in tiles of any pyramid level; with the view zoomed out it read the height of another point, closer to the upper left corner of the tile](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* [Stereoscopic orthophoto: after the level of detail is changed, the tiles of the maximum pyramid level are reloaded and the automatic Z gives a height again in areas where no fine tiles are loaded](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* [Stereoscopic orthophoto: the automatic Z, the vector projection and the level of detail combo can no longer close Digi3D.AI if used before the first drawing of the orthophoto](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* [Stereoscopic orthophoto: tile memory no longer grows without limit; the height maps of evicted tiles and of tiles read when projecting vectors are freed, as are tiles not drawn for 100 frames](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* With two windows open with the same stereoscopic orthophoto or point cloud sensor, closing one destroyed the docking panel of the other; each sensor now destroys only the panels it created
* [An installation with the stereoscopic orthophoto but without point clouds did not install MotorOpenGL.dll, and Digi3D.AI could not load the sensor; the stereoscopic orthophoto feature now installs MotorOpenGL.dll](https://www.digi21.net/Ayuda/p/ortofoto-estereoscopica)
* In a window opened with a stereoscopic orthophoto or a point cloud, quick model switching stopped accepting requests; now the projects panel opens the model in a new window
* [A .vec file can be opened as a drawing file again, appears again in the drawing file selection dialog and digitizing with it works again; the digitized entities are not saved in the .vec file](https://www.digi21.net/Ayuda/p/vec)
* [Quick model change: with a local TIFF image that Digi3D.AI cannot read, the conversion dialog is shown and, if accepted, the model is loaded when the conversion ends; before, the change failed](https://www.digi21.net/Ayuda/p/localizada-una-imagen-no-preparada-para-digi3d-ai)
* [BINTOP and BINTRAM write the entities to the errors file again when it is a .vec file; the file was left with only the header](https://www.digi21.net/Ayuda/p/vec)
* [With the “Digital Terrain Model based on existing geometries” command (DTM menu) and a non-rectangular boundary, the in-memory DTM did not project Z over part of the boundary; it now projects Z over the whole boundary](https://www.digi21.net/Ayuda/p/triangular)
* When opening a truncated or damaged .mdt digital terrain model, Digi3D.AI shows an error; before, it could hang
* [Coordinate output through the serial port: the centimeter and millimeter formats round the coordinates; with satellite images and a locked Z, 1 cm or 1 mm less was sometimes sent](https://www.digi21.net/Ayuda/p/envio-de-coordenadas-por-puerto-serie)
* [Serial port coordinate output: with the data button held down, Digi3D.AI no longer sends an intermediate pedal release that the receiving program could read as a second click, and only the active photogrammetric window sends coordinates](https://www.digi21.net/Ayuda/p/envio-de-coordenadas-por-puerto-serie)
* Digi3D.AI loads the DTM importer again on computers where the configuration saved by an earlier installation indicated that it was loaded from WinSxS
* With a network dongle, if the dongle reports an error when Digi3D.AI starts (for example, because it has no license), Digi3D.AI releases the seat; before, the seat stayed occupied until Digi3D.AI was closed
* .NET programming: if an import and export extension cannot be initialized, for example the PDF one in a program without Microsoft.WindowsDesktop.App, DigiTab.Load logs the error and loads the others; before, it threw an exception
