# Digi3D.AI 2027.0.0.422

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Released on 11/1/2026.

## New features

* The Reference files dialog has a check box to open the drawing file without loading the associated photogrammetric project or model
* The installer includes a code table in English
* The AI chat panel shows its texts in the interface language
* [The .reference\_files.json file of each drawing file can store the photogrammetric project and model, and Digi3D.AI loads them when the drawing file is opened](https://www.digi21.net/Ayuda/p/almacenar-el-proyecto-o-el-modelo-fotogrametrico)
* [The About dialog shows the program version](https://www.digi21.net/Ayuda/p/acerca-de-digi3d-ai)
* The new version notice uses the theme colors
* [Photogrammetric projects (.d3dprj) accept pairs of the RPC Satellite (stereoscopic) sensor, with automatic pair switching](https://www.digi21.net/Ayuda/p/rpc)
* [New GROUND\_CURSOR command: draws around the cursor a circle with the given radius in ground units, in the drawing window and in the photogrammetric window](https://www.digi21.net/Ayuda/p/cursor-terreno)
* [The RPC Satellite (stereoscopic) sensor shows on the images the ground control points measured for the RPC block adjustment](https://www.digi21.net/Ayuda/p/ajuste-en-bloque-de-rpcs)
* [The RPC block adjustment panel shows the root mean square error, the mean and the maximum absolute value of each residual column](https://www.digi21.net/Ayuda/p/ajuste-en-bloque-de-rpcs)
* [When OK is clicked, the RPC block adjustment panel saves an adjustment report with the coordinate reference systems of the ground and of the RPCs](https://www.digi21.net/Ayuda/p/ajuste-en-bloque-de-rpcs)
* [BINTRAM, SPIT\_LINES and SPLIT\_VISIBLES\_LINES add to the Tasks panel an error for each line they could not split, with the reason](https://www.digi21.net/Ayuda/p/partir-lineas)
* [The New project dialog asks whether to overwrite the copied model when the new model would be saved to the same .d3d file](https://www.digi21.net/Ayuda/p/nuevo-proyecto-2)
* If a photogrammetric model cannot be opened, the message shows the cause; for example, the name and path of the missing geoid grid

## Fixes

* Compressing the drawing file and then redrawing closed the program if the file had deleted polygons with holes or deleted complexes
* In the aerial triangulation measurement, selecting a point with a thumbnail could close the program
* Opening a PointCloud model whose clouds could not be read showed «Bad optional access»; now the program reports that no cloud could be read
* Cancelling the preparation of an image showed an error message
* After changing the code table, the Python rules and quality controls of the previous table were still active
* Opening a file in a format without parameters (WMS, GeoJSON, IFC, WKT...) showed an empty import parameters dialog
* LOAD\_F did not warn when no importer accepted the file extension
* The %ENTITY\_\*\_ROUND\_INT% macros truncated instead of rounding to the nearest integer
* Some startups failed while loading the Sentinel license generation library; now it is only loaded when needed
* Many English interface texts corrected, and controls resized so that texts are not cut off
* The horizontal and vertical coordinate reference system parameter dialogs closed the program
* .bind drawing files with a connection string could not be opened if their configuration had been saved with the interface in another language
* Fixed English interface texts that were truncated, untranslated or misspelled
* [AREA, DRAW\_PERIMETER and DRAW\_PERIMETER\_3D closed the program if Enter was pressed in the status bar after placing the text](https://www.digi21.net/Ayuda/p/area)
* Adding geometries to a drawing file could close the program if the list of reference files had, before it, a file that is not drawn in the photogrammetric window, such as a raster, a WMS layer, a KML file or a point cloud
* Drawing a point with a symbol in the photogrammetric window closed the program if another reference file had been loaded after its drawing file
* In Python, the object returned by geographic\_calculator became invalid and could close the program after loading a reference file or opening another drawing
* [From the second iteration on, the RPC block adjustment did not honor the a priori precisions of the correction parameters and of the ground control points](https://www.digi21.net/Ayuda/p/ajuste-en-bloque-de-rpcs)
* Absolute orientation failed from the third measured point on when the vertical reference system had a geoid model, such as EGM2008
* Digi3D.AI did not find the EGM2008 geoid grids with the \_SE suffix; the installer creates links with the EPSG catalog name
* [BINTRAM, SPIT\_LINES and SPLIT\_VISIBLES\_LINES did not split any line when the drawing file rejected one of the pieces; now only the line of that piece stays unsplit](https://www.digi21.net/Ayuda/p/partir-lineas)
* [When splitting lines, a back-and-forth piece \[A, B, A\] was left with two identical vertices and the drawing file rejected it](https://www.digi21.net/Ayuda/p/bintram)
* The geographic calculator computed wrong distances, azimuths and areas in geographic systems whose angular unit is not the degree, such as NTF (Paris)
* [The area of a polygon in a geographic system was larger than on the ellipsoid: 0.2 % for a 5° × 5° polygon at 40° latitude](https://www.digi21.net/Ayuda/p/area)
