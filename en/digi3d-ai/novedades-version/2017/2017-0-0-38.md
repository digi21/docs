# Digi3D.AI 2017.0.0.38

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Released on 6/27/2017.

## New features

* Added new macro $(HelpDirectory) that is replaced by the help directory configured by the user
* New order SHOW\_HELP that shows in the help window the HTML file whose path is passed by parameters to this command
* Added menu option Flood / Delete code
* Changed the title for the menu Flooging/Generate flooding by Flooding/Generate topology for flooding
* New option menu: Flooding/Unload topology for flooding
* Modification in the UNDO policy. In the version 2017.0.0.32 a change in the policy of UNDO was made that was not allowed to execute this order if the program was not in "Ready" mode. We have relaxed this policy, and now it is not allowed to execute the UNDO command only if it is in the middle of a transaction (ie, an order is being executed and it has not yet been finalized and has made some changes to the drawing file)
* Added Flooding/Discard topology menu option
* When adding new features to a Shapefile file, Geomedia does not recognize the geometries that are outside the boundaries of the digitized geometries with Digi3D.NET
* New command: LOAD\_ASSEMBLY to load .NET assemblies without having to modify the registry
* Now the code tables can be downloaded from WEB servers

## Fixes

* The snap faults with polygons with holes. In the 2017.0.0.14 version, a significant change was made in the snaps to allow geographic coordinates to work with precision from 1e-13, and this caused that the attempts with holes were not snapped correctly.
* The tentative fails if the difference of coordinate Z between the cursor and the entity to be attempted is very large
* When an entity is snapped, the cross that marks the snap coordinates in the drawing window does not appear until the screen is regenerated or the zoom level is changed
* When you add codes by flooding, if you flood a hole in a polygon, you add the code to the entities that define the hole
* When analyzing the overlap relationship between two areas, if the second area analyzed had a point in common with the first vertex of the first area, the program could crash
* Fixed a bug that could cause the program to terminate unexpectedly if .NET scripts were executed on the drawing file and the drawing file was closed and a new one was loaded.
* On computers without the Visual Studio 2010 Redistributable Package when accepting the Configuration dialog box, an error message is displayed stating that the server is bussy
* The SELECT\_POLIGONO\_NUEVO order sometimes unexpectedly ends the program
* The ReadOnlyPolygon.InteriorPoint property does not correctly calculate the centroid if the polygon has holes
* When parsing a topology the returned ClosedLoopWithHoles object never has associated centroids
* When Compressing .SHP Files, the Program Quits Unexpectedly
* When executing the BINTRAM command from the command line the parameters of grouping vertices and inserting vertices by tolerance are not correctly interpreted
* The operator - of type Digi21.Math.Point3D does not correctly subtract the Z coordinate
