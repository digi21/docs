# Digi3D.AI 2017.0.0.19

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Released on 3/11/2017.

## New features

* Updated ERDAS ECW JPEG 2000 library to version 5.3.0 to avoid dependencies with Visual Studio 2010
* Updated Kicense Suite built into installer to the version 17.0.0.3
* Updated the MrSID\_DSDK library to the version 9.5.4.4703 to avoid dependences with Visual Studio 2010
* [Improved loading speed of JPEG images](https://blog.digi21.net/2017/02/27/mejora-impresionante-en-la-velocidad-de-carga-de-imagenes-jpeg/)
* Updated the extension of ECW and Jpeg2000 files to allow loading images composed by several images
* Now can be indicated the coordinate reference systems when loading ArcGi's ASCII DEM format
* Now you can load ArcGis DEM ASCII format with values of type XLLCENTER and YLLCENTER
* [Added Side-by-side 3D stereoscopic mode](https://blog.digi21.net/2017/03/10/nuevo-modo-de-visualizacion-estereoscopica/)
* Improved refresh performance in the photogrammetric window for stereoscopic modes that do not require Quad-Buffer
* New command COPY\_DATABASE\_ATTRIBUTES\_ENTITY\_ENTITY. This command copies database attributes from one entity to another.
The parameters of this command are \[source field name\] \[target field name\]
* Added support for loading Pleyades models with images formed by the concatenation of several images

## Fixes

* Fixed a problem related to BBDD attributes when storing a geometry that intersects with another geometry that links to the same database table if the auto insert vertices are active at the intersection. If this happened, the attributes of the last entity that was just rewritten were preserved in the database attributes panel, so that the geometry we are drawing was stored with the attributes of the last geometry that was just rewrite.
* Solved a problem with communication with Google Earth
* Installing Digi3D.NET on a New computer does not install .NET Framework 4.5.2. The Digi3D.NET boostrapper has been modified to install Microsoft .NET Framework 4.5.2 instead of 4.0
* When loading a satellite model whose RPC parameters are in a .BLK file, if the paths of the images to load and those that appear in the .BLK do not match, the RPC parameters are not found
