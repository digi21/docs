# Digi3D.AI 2015.20.22.0

Publicada el 03/05/2015.

## Novedades

* Los paneles de orientación (interna/relativa/aerotriangulación/absoluta) ahora memorizan su posición. Se ha modificado el programa para que los paneles de orientaciones ahora memoricen su posición y tamaño.

Como contrapartida, si el programa está configurado para el uso de varios monitores, ahora los paneles no se acoplan a la ventana fotogramétrica, sino que se acoplan al marco principal de la aplicación.
* Mejora en la comunicación de errores en el Visor de Registro de Eventos de Windows. Ahora los componentes base de la aplicación comunican errores/advertencias/mensajes de manera personalizada en el visor de eventos de recursos de Windows.
* Cambio de nombre y significado en variable RotacionMontaje en archivo de cámara. Ahora la variable RotacionMontaje pasa a llamarse Rotacion.
Cambiar la rotación de la cámara modifica la ubicación del sistema fiducial, para simular que el eje de la X siempre apunta en el sentido del vuelo.
Ahora, cambiar la variable Rotacion no fuerza la rotación de las imágenes en pantalla. ([commit](http://blog.digi21.net/2015/05/01/rotar-la-imagen-con-un-programa-externo-o-con-el-menu-de-digi3d-net-no-es-lo-mismo))

## Correcciones

* Mejoras en el cálculo de coordenadas aproximadas relativa y aerotriangulación. Se ha solucionado un problema relacionado con el cálculo de coordenadas aproximadas para la orientación relativa y absoluta con imágenes rotadas.
* Solucionado cuelgue al cargar proyecto fotogramétrico con cámaras inexistentes. Si se carga por un proyecto en el que a todos los modelos tienen como ruta del archivo de cámara una ruta inexistente, Digi3D.NET mostrará el cuadro de diálogo de localización del archivo de cámara tantas veces como fotos tenga el proyecto. Si el usuario Esc en todos ellos, al finalizar el proceso de comprobación Digi3D.NET carga el primer modelo del archivo de proyecto. El programa finaliza inesperadamente.
* El sensor Ortofoto Estereoscópica devuelve un sistema de corodenadas de referencia 2D. Hasta ahora el sensor ortofoto estaba indicando a Digi3D.NET que su sistema de referencia de coordenadas era el devuelto por la ortofoto.
Se ha modificado este comportamiento para que se devuelva el sistema asociado al modelo digital del terreno, y en caso de que éste sea 2D, se devolverá un sistema de referencia de coordenadas compuesto 2D + vertical desconocido.
* Solucionado cuelgue de la aplicación al transformar imágenes en la ventana fotogramétrica. Se ha solucionado un problema por el cual el programa podía finalizar inesperadamente si se cambiaba bruscamente la posición de la ventana fotogramétrica mientras los hilos trabajadores estaban calculando la imagen transformada debido a que había activa una transformación como rotación o epilolar.

Como contrapartida ahora el programa puede que obligue al usuario a esperar una fracción de segundo si se cambia de zoom y se está transformando en segundo plano una tesela de la imagen.
* Las órdenes zoominf y zoomsup no se ejecutan. Se ha solucionado un fallo pues el instalador estaba instalando estas órdenes con un nombre incorrecto.
