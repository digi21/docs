## Novedades

* Ahora el valor por defecto de Consumo de Memoria bajo demanda es verdadero. Esta configuración reduce el consumo de memoria de acceso aleatorio (RAM) al cargar modelos de un proyecto de cambio rápido de modelos.
* Ahora se comparten componentes con la suite de licencias para ocupar menos espacio en el disco duro del cliente.
* Se ha añadido compatibilidad para cargar proyectos .smtxml e imágenes .smti de Summit Evolution. ([commit](http://blog.digi21.net/2015/07/01/cargando-de-forma-nativa-proyectos-de-summit-evolution-con-digi3d-net/))
* El cuadro de diálogo Nuevo Proyecto ya no sobrescribe archivos .d3d. Ya no se crea un archivo .d3d cada vez que se carga un modelo fotogramétrico.
Hemos modificado la pestaña Sensores Fotogramétricos para evitar crear el archivo cada vez que se abre. ([commit](http://blog.digi21.net/2015/07/05/mejoras-en-el-cuadro-de-dialogo-nuevo-proyecto-de-digi3d-net/))
* Ya no se solicita el archivo de cámara al crear un modelo de cámara cónica. ([commit](http://blog.digi21.net/2015/07/07/mejoras-al-especificar-el-sistema-de-referencia-de-coordenadas-de-un-modeloproyecto-de-aerotriangulacion/))
* Ahora el programa solicita el sistema de referencia de coordenadas (SRC) al cargar un modelo fotogramétrico que no tiene uno asociado. ([commit](http://blog.digi21.net/2015/07/07/mejoras-al-especificar-el-sistema-de-referencia-de-coordenadas-de-un-modeloproyecto-de-aerotriangulacion/))
* Ahora el cargador de proyectos Inpho carga el SRC asociado. Se ha modificado el cargador de proyectos de Inpho (\*.prj) para extraer del archivo el SRC asociado con el proyecto.
* Ahora puedes abrir Google Maps en un navegador con un mapa de la ubicación geográfica representada en la ventana fotogramétrica. ([commit](http://blog.digi21.net/2015/07/08/abre-una-ventana-de-google-maps-en-la-ubicacion-de-la-ventana-fotogrametrica/))
* Ahora puedes abrir un navegador con Bing Maps mostrando un mapa en las coordenadas geográficas representadas en la ventana fotogramétrica. ([commit](http://blog.digi21.net/2015/07/08/abre-una-ventana-de-bing-maps-en-la-ubicacion-de-la-ventana-fotogrametrica/))
* Se han eliminado dependencias con el software Aerotri que no se utilizaban.

## Correcciones

* Se ha corregido un problema que impedía mostrar el cuadro de diálogo de Orientación Relativa.
* Se han unificado las tablas de las versiones de 32 y 64 bits. La ayuda de los programas remite en ocasiones a la carpeta %ProgramData%\\Digi3D.NET; sin embargo esa carpeta no existía porque los instaladores de 32 y 64 bits intercalaban la plataforma en el nombre de la carpeta.
* Se ha solucionado un problema que impedía cambiar los ejes al cambiar de pasada en un proyecto con distintas pasadas. En pasadas alternas, el movimiento del dispositivo de entrada era el contrario al esperado.
* Se han revisado las órdenes que no mostraban su estado al pasarles el carácter ? como parámetro.
* Se ha corregido el cálculo de las correcciones de RapidCal.
* Se ha solucionado un problema que podía hacer que el programa finalizase inesperadamente con un cambio rápido de modelos. Si no había una ventana de dibujo abierta y se provocaba un cambio rápido de modelos, el programa finalizaba inesperadamente.
* Se ha solucionado un problema al calcular el histograma en imágenes de 16 bits. El programa finalizaba inesperadamente al calcular el histograma en imágenes de 16 bits.
* Se ha corregido el cargador para que distinga entre archivos TIFF que contienen imágenes y archivos TIFF que contienen modelos digitales del terreno (MDT). Antes, los archivos TIFF que contenían un modelo digital del terreno se mostraban como ortofotos. Ahora el cargador identifica los archivos TIFF que contienen modelos digitales del terreno como MDT.
