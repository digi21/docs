# Digi3D.AI 2018.0.10.0

Publicada el 16/03/2018.

## Novedades

* Ahora se admite la carga de archivos .PYR. Además el programa generador de niveles piramidales puede crear archivos .PYR. ([commit](http://blog.digi21.net/2018/03/18/anadido-soporte-para-archivos-pyr))
* Modificado el cálculo de la matriz de nivelación para imágenes satelitales. Ahora es compatible tanto con parámetros RPC en geográficas como en UTM
* Añadido soporte para carga de archivos .PRJ de Inpho de tipo satelital y con coeficientes corregidos. Si se localizan coeficientes corregidos se cargan estos si no, se cargan los originales.
* Ahora al cargar archivos de proyecto de Inpho para sensor satelital, el programa no asume que el sistema de referencia de coordenadas es geográfico WGS84, sino que obtiene el sistema del archivo .PRJ
* Ahora el cargador de archivos de proyecto de Summit Evolution para sensores satelitales permite cargar proyectos que no estén epipolarizados
* Ahora se puede configurar si se desea que el programa solicite el sistema de referencia de coordenadas vertical en caso de que el modelo fotogramétrico cargado proporcione uno en 2D. Podemos configurar este comportamiento en Herramientas/Configuración/Sistemas de referencia de coordenadas/Solicitar sistema vertical para sensores ([commit](http://blog.digi21.net/2018/03/18/evitando-que-digi3d-net-solicite-el-sistema-de-referencia-de-coordenadas-vertical-si-la-orientacion-del-sensor-no-lo-proporciona))
* Ahora el importador de Pix4D también carga los archivos \_calibrated\_external\_parameters.txt. De esta manera ya pueden cargar estos archivos sin modificar (hasta ahora había que renombrarlos a .EO además de eliminar las extensiones de las imágenes para cada una de las orientaciones que contiene) ([commit](http://blog.digi21.net/2018/03/18/mejorado-el-soporte-de-pix4d))
* Añadido soporte para aproximar epipolares en las imágenes satelitales ([commit](http://blog.digi21.net/2018/03/18/anadido-soporte-para-aproximar-epipolares-en-las-imagenes-satelitales))
* Añadido en el menú de ventana fotogramétrica una opción para calcular la rectificación epipolar de modelos satelitales
* Simplificado el menú de Ventana fotogramétrica/Transformación de las imágenes al cargar un modelo de sensor cónico. Ahora se muestra una única opción para el cálculo de la epipolar. Además si la rotación actual coincide con la orientación epipolar, se muestra una marca en el menú. Se puede indicar en la configuración el tipo de epipolar a calcular al seleccionar la opción. ([commit](http://blog.digi21.net/2018/03/18/mejoras-de-interfaz-de-usuario-para-epipolares-para-el-sensor-conico))
* Mejoras en la comunicación de errores al cargar modelos satelitales y de cámara cónica. Ahora las extensiones de RPC únicamente intentan cargar el archivo si es compatible y lanzan excepciones con errores en caso de localizar algún error en el archivo. Ahora el cargador no captura las excepciones sino que se las pasa a Digi3D.NET para que se las muestre al usuario. ([commit](http://blog.digi21.net/2018/03/19/mejoras-en-la-comunicacion-de-errores-al-cargar-modelos-satelitales-y-de-camara-conica))
* Ahora el cargador de archivos .EO permite que en el archivo .EO aparezca la extensión de la imagen. Hasta ahora el programa localizaba únicamente las orientaciones de las imágenes si en el archivo .EO no aparecía la extensión de la imagen. Debido a que cada vez más programas generan archivos .EO en los que se añade la extensión de la foto en la primera columna de las orientaciones, hemos modificado el programa para que sea capaz de localizar la orientación tanto si aparece la extensión como si no.

## Correcciones

* Si se carga un archivo .TIF y se generan advertencias, el programa genera fugas de memoria.
* Al cargar modelos satelitales el programa puede dejar fugas de memoria.
* Solucionado problema al proyectar\_dem, podría darse el caso de que el número de filas y/o columnas calculadas no coincidiera con el esperado
* Solucionado un problema al IR\_PRINCIPIO cuando la Z de la ventana fotogramétrica estaba bloqueada
* Solucionado un problema por el cual al cambiar los parámetros de visualización de una clasificación en un archivo LAS, los cambios no se veían en la ventana fotogramétrica hasta cerrarla y volverla a abrir.
* Solucionado un problema cuando un test de calidad de la cartografía devolvía más de una incidencia para la misma entidad, al hacer doble clic sobre la tarea, se mostraba una geometría incorrecta.
* Solucionado además que si se lanzaba una excepción de tipo DatabaseAttributeException no se generaban tareas en el panel de tareas.
* Si se localiza un error desconocido al cargar un proyecto fotogramétrico mediante el panel de proyectos fotogramétricos, el programa finaliza inesperadamente
* Si en un archivo de proyecto de PhotoScan aparecen varias calibraciones para una cámara, se carga siempre la primera independientemente de que sea la ajustada o no
