# Digi3D.AI 2018.0.6.0

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Publicada el 14/02/2018.

## Novedades

* Se ha añadido la orden FORMAR\_POLIGONOS. ([commit](https://blog.digi21.net/2018/02/19/nueva-orden-formar_poligonos/))
* Se ha añadido compatibilidad para almacenar geometrías virtuales en archivos de dibujo basados en base de datos como Shapefiles.
* Ahora se puede configurar si el tentativo se acepta con el botón/pedal de Dato si la orden que se está ejecutando es la orden LINEA. Esta nueva opción de configuración aparece en Herramientas/Configuración/Tentativos.
* Se ha añadido una opción para indicar si, al finalizar INSERTAR\_HUECO, la orden debe eliminar la línea seleccionada como hueco.
* La orden MOD\_MULTIPLE no elimina la línea que define la nueva geometría cuando finaliza su ejecución.
* Ahora las órdenes no realizan regeneraciones de pantalla innecesarias cuando el usuario se desplaza sobre un polígono que ya se ha rellenado de color.
* Ahora, al ejecutar las órdenes TAREA+ y TAREA- para tareas que desplazan la ventana de dibujo a unas coordenadas determinadas, la ventana fotogramétrica también se desplaza a las coordenadas de la tarea si está abierta.
* Se ha añadido soporte para duplicar polígonos a la orden DUP.

## Correcciones

* Se ha solucionado un problema en el cálculo de centroides en polígonos. No se estaba calculando correctamente el centroide en polígonos con huecos.
* Al ir al punto de origen en modelos de PhotoScan con nodos camera/reference el programa lleva a coordenadas incorrectas. Ahora, si el programa localiza el atributo zMedia, ignora el nodo camera/reference, pues la coordenada Z de ese nodo no está en el terreno. Ahora además el programa asume que las coordenadas que aparecen en camera/reference son siempre coordenadas geográficas.
* Los archivos TIFF teselados con teselas rectangulares en vez de cuadradas se visualizan con artefactos.
* La orden DESPLAZAR\_ORIGEN duplica el polígono si lo que se desplaza es el origen de un hueco del polígono.
* Algunas órdenes duplican geometrías al ejecutarse con el flag AUTO\_INSERTAR\_VERTICE\_INTERSECCION\_AL\_FINALIZAR\_LINEA. Se ha modificado el comportamiento del programa al almacenar geometrías con el flag AUTO\_INSERTAR\_VERTICE\_INTERSECCION\_AL\_FINALIZAR\_LINEA activado. Ahora las modificaciones de geometrías que interseccionan con las geometrías que se acaban de almacenar se realizan tras finalizar cada orden en vez de realizarse cada vez que una orden añade una geometría al archivo de dibujo.
* En ocasiones el programa muestra ciertas geometrías que tienen un código cuya visualización está desactivada. Si recuperabas una geometría eliminada, la geometría seguía visible aunque ejecutases una orden para ocultarla.
* En algunas ejecuciones, el consumo de memoria del programa aumenta progresivamente al formar topologías para inundación.
* Desde que se añadió la funcionalidad de mostrar múltiples errores semánticos en una única geometría, al hacer el análisis bajo demanda el programa no muestra los errores en la lista de tareas.
