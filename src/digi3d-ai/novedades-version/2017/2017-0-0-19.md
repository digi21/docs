# Digi3D.AI 2017.0.0.19

Publicada el 11/03/2017.

## Novedades

* Actualizada la librería ERDAS ECW JPEG 2000 a la versión 5.3.0 para evitar dependencias con Visual Studio 2010
* Actualizada la suite de licencias incorporada en el instalador a la versión 17.0.0.3
* Actualizada la librería MrSID\_DSDK a la versión 9.5.4.4703 para evitar dependencias con Visual Studio 2010
* Mejorada la velocidad de carga de imágenes JPEG ([commit](https://blog.digi21.net/2017/02/27/mejora-impresionante-en-la-velocidad-de-carga-de-imagenes-jpeg/))
* Actualizada la extensión de carga de archivos ECW y Jpeg2000 para permitir cargar imágenes compuestas por varias imágenes
* Ahora se pueden indicar sistemas de referencia de coordenadas al cargar archivos DEM en formato ASCII de ArcGis
* Ahora se pueden cargar archivos DEM en formato ASCII de ArcGis con valores de tipo XLLCENTER e YLLCENTER
* Añadido el modo de visualización estereoscópica Lado-a-lado (mitad) ([commit](https://blog.digi21.net/2017/03/10/nuevo-modo-de-visualizacion-estereoscopica/))
* Mejorado el rendimiento de actualización en la ventana fotogramétrica para los modos estereoscópicos que no requieren Quad-Buffer
* Nueva orden COPIA\_ATRIBUTOS\_BBDD\_ENTIDAD\_EN\_ENTIDAD. Esta orden copia atributos de base de datos de una entidad en otra.
Los parámetros de esta orden son \[nombre del campo origen\] \[nombre del campo destino\]
* Añadido soporte para la carga de modelos de Pleyades con imágenes formadas por la concatenación de varias imágenes

## Correcciones

* Solucionado un problema relacionado con atributos de BBDD al almacenar una geometría que se cruza con otra geometría que enlaza con la misma tabla de base de datos si está activo el auto insertar vértices en la intersección. Si se daba esta circunstancia, en el panel de atributos de base de datos se mantenían los atributos de la última entidad que se acaba de reescribir, de manera que la geometría que estamos dibujando se almacenaba con los atributos de esta última geometría que se acaba de reescribir.
* Solucionado un problema con la comunicación con Google Earth
* Al instalar Digi3D.NET en un equipo nuevo no se instala .NET Framework 4.5.2. Se ha modificado el boostrapper de Digi3D.NET para que instale Microsoft .NET Framework 4.5.2 en vez de 4.0
* Al cargar un modelo satelital cuyos parámetros RPC están en un archivo .BLK, si las rutas de las imágenes a cargar y las que aparecen en el archivo .BLK no coinciden, no se localizan las orientaciones
