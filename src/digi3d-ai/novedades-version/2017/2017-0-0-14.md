# Digi3D.AI 2017.0.0.14

<!-- Generado desde la base de datos de digi21.net. No editar a mano. -->

Publicada el 28/01/2017.

## Novedades

* Se ha añadido una opción al cuadro de diálogo de sustituir valores de base de datos para sustituir cualquier valor por uno determinado.
* Se ha actualizado la dependencia al componente Glew a su última versión.
* Se han cambiado las fechas de copyright para incluir 2017.
* Se ha mejorado el algoritmo para comprobar si dos vectores están alineados con precisiones inferiores a 1e-15.
* Ahora, antes de almacenar una geometría de tipo polígono, se eliminan automáticamente los puntos dobles.
* Ahora la orden COMPRIMIR no recibe parámetros. Hasta esta versión, la orden COMPRIMIR podía recibir como parámetros dos indicadores para indicar si se debían eliminar puntos dobles. Se ha eliminado esta funcionalidad de la orden COMPRIMIR pues no era compatible con archivos de Geomedia.
* Ahora el exportador de Geomedia no permite almacenar como distintas dos coordenadas cuya diferencia sea inferior al sigma activo.
* Se ha creado la orden ELIMINAR\_PUNTOS\_DOBLES.
* Ahora en instalaciones de 64 bits el título del programa "Editor de Tablas de Códigos" pasa a ser "Editor de Tablas de Códigos x64".
* Ahora en instalaciones de 64 bits el título del programa "Generador de niveles piramidales" pasa a ser "Generador de niveles piramidales x64".
* Se ha añadido la orden EXPORTAR\_ENTIDADES\_SELECCIONADAS. ([commit](https://blog.digi21.net/2017/01/24/exportar-las-entidades-seleccionadas/))
* Se ha añadido la orden DETECTAR\_BUCLES. ([commit](https://blog.digi21.net/2017/01/23/detectar-bucles/))
* Se ha añadido la orden DETECTAR\_SEGMENTOS\_CORTOS. ([commit](https://blog.digi21.net/2017/01/25/detectar-segmentos-cortos/))
* Se ha modificado el cuadro de diálogo de cambiar valores de base de datos para que se muestre con el tema activo.

## Correcciones

* El programa finaliza inesperadamente cargando archivos DWG que generan mensajes de error.
* Con sigmas de doble precisión, como 1e-15, los tentativos no tentativan en la proyección correcta.
* Si se especifica una ondulación del geoide manualmente, el programa no muestra los vectores en su coordenada Z.
* Si se selecciona como sistema de referencia de coordenadas vertical EGM2008, la ondulación del geoide calculada en coordenadas de longitud negativas muy cerca de la latitud 0 era incorrecta. Se ha solucionado este problema, ocasionado por un error al almacenar en caché la rejilla EGM2008.
* Se ha solucionado el problema del cuadro de diálogo de introducción de ondulación del geoide que permitía introducir la ondulación sin seleccionar previamente la introducción manual.
