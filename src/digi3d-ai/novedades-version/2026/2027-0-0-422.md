## Correcciones

* Comprimir el archivo de dibujo y después redibujar cerraba el programa si el archivo tenía polígonos con huecos o complejos borrados
* En la medida de aerotriangulación, elegir un punto con instantánea podía cerrar el programa
* Al abrir un modelo PointCloud cuyas nubes no se podían leer se mostraba «Bad optional access»; ahora se indica que no se pudo leer ninguna nube
* Cancelar la preparación de una imagen mostraba un mensaje de error
* Al cambiar de tabla de códigos seguían activas las reglas y los controles de calidad de Python de la tabla anterior
* Al abrir un archivo de un formato sin parámetros (WMS, GeoJSON, IFC, WKT...) se mostraba vacío el cuadro de parámetros de importación
* CARGA\_F no avisaba cuando ningún importador aceptaba la extensión del archivo
* Las macros %ENTITY\_\*\_ROUND\_INT% truncaban en lugar de redondear al entero más próximo
* Algunos arranques fallaban al cargar la biblioteca de generación de licencias de Sentinel; ahora solo se carga cuando se necesita
* Numerosos textos de la interfaz inglesa corregidos y controles ajustados para que no se corten
* Los cuadros de diálogo de parámetros del sistema de referencia de coordenadas horizontal y vertical cerraban el programa
* Los archivos de dibujo .bind con cadena de conexión no se abrían si su configuración se había guardado con la interfaz en otro idioma
* Corregidos textos de la interfaz en inglés que salían cortados, sin traducir o con erratas
* [AREA, DIBUJA\_PERIMETRO y DIBUJA\_PERIMETRO\_3D cerraban el programa si se pulsaba Intro en la barra de estado después de colocar el texto](https://www.digi21.net/Ayuda/p/area)
* Añadir geometrías a un archivo de dibujo podía cerrar el programa si delante en la lista de archivos de referencia había un archivo que no se dibuja en la ventana fotogramétrica, como un ráster, un WMS, un KML o una nube de puntos
* Dibujar en la ventana fotogramétrica un punto con símbolo cerraba el programa si después de cargar su archivo de dibujo se había cargado otro archivo de referencia
* En Python, el objeto que devuelve geographic\_calculator dejaba de ser válido y podía cerrar el programa después de cargar un archivo de referencia o abrir otro dibujo
* [A partir de la segunda iteración, el ajuste en bloque de RPCs no respetaba las precisiones a priori de los parámetros de corrección ni de los puntos de apoyo](https://www.digi21.net/Ayuda/p/ajuste-en-bloque-de-rpcs)
* La orientación absoluta fallaba a partir del tercer punto medido si el sistema de referencia vertical tenía un modelo de geoide, como EGM2008
* Digi3D.AI no encontraba las mallas del geoide EGM2008 con el sufijo \_SE; el instalador crea enlaces con el nombre del catálogo EPSG
* [BINTRAM, PARTIR\_LINEAS y PARTIR\_LINEAS\_VISIBLES no partían ninguna línea si el archivo de dibujo rechazaba uno de los tramos; ahora solo queda sin partir la línea de ese tramo](https://www.digi21.net/Ayuda/p/partir-lineas)
* [Al partir líneas, un tramo de ida y vuelta \[A, B, A\] quedaba con dos vértices iguales y el archivo de dibujo lo rechazaba](https://www.digi21.net/Ayuda/p/bintram)
* La calculadora geográfica calculaba mal distancias, acimuts y áreas en sistemas geográficos cuya unidad angular no es el grado sexagesimal, como NTF (Paris)
* [El área de un polígono en un sistema geográfico era mayor que la del elipsoide: un 0,2 % en un polígono de 5° × 5° a 40° de latitud](https://www.digi21.net/Ayuda/p/area)
